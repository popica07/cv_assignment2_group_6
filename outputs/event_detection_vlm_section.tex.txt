\section{Event Detection using Vision--Language Models (VLMs)}
\label{sec:vlm-event-detection}

\subsection{Overview and Objective}
\label{subsec:vlm-overview}

The objective of this section is to detect the salient events present in each
of the four videos using a small--scale Vision--Language Model (VLM) in two
configurations: (a)~\textbf{event-only} predictions producing an unordered
list of detected events, and (b)~\textbf{event~+~timestamp} predictions
producing an ordered list of events with approximate temporal localisation
(\texttt{MM:SS--MM:SS}). The VLM outputs are then parsed and matched against
the human annotations described in Section~\ref{sec:annotation} via
sentence-embedding similarity. We finally conduct a failure analysis to
understand which categories of events are systematically missed and we
document the full history of prompts that we explored.

\subsection{Model Selection}
\label{subsec:vlm-model}

We selected \textbf{SmolVLM2-2.2B-Instruct}\footnote{\url{https://huggingface.co/blog/smolvlm2}}
because it (i)~runs natively on Apple Silicon through the \texttt{mps}
backend; (ii)~accepts a sequence of sampled frames in chat-template format,
which fits our temporal sampling pipeline; and (iii)~at $\sim$2.2B parameters
in \texttt{float16} it fits comfortably in $\sim$4.4\,GB of GPU memory,
roughly four times less than the same model in \texttt{float32}. The model is
loaded with \texttt{device\_map="auto"} and image tile splitting is disabled
(\texttt{processor.image\_processor.do\_image\_splitting=False}) to prevent the
$9\times$ tile explosion that otherwise causes out-of-memory errors on MPS.

\label{subsec:vlm-sampling}

(\texttt{sample\_frames\_sparse}). One frame is captured every
$\Delta t = 2$ seconds, giving $\lfloor T/\Delta t\rfloor + 1$ frames per
video where $T$ is the video duration in seconds. Each frame is stored as a

\label{subsec:vlm-target-count}

descriptions and long clips tend to be over-summarised. To keep the model

\subsection{Prompt Engineering and Prompt History}
\label{subsec:vlm-prompts}

We explored \emph{four} prompting strategies, two for the event-only setting
and two for the event+timestamp setting. All prompts share the same target
event range and the same numbered output format
\texttt{Salient event $N$:~description}.

\paragraph{Prompt~1 (event-only, baseline).}
The original ``salient event'' formulation from the assignment statement.

\begin{lstlisting}[style=prompt,caption={\texttt{event\_only\_prompt1} -- baseline.},captionpos=b]
You are a video analyst. The frames below are sampled at regular intervals
from a video and shown in chronological order.
Task: list the salient events of the video.
- Each event must describe a distinct activity or scene.
- Merge consecutive similar actions into one event.
- Return between {min_events} and {max_events} events.

Number each event from 1, one per line:
1. <event description>
2. <event description>
Do not add any other text.
\end{lstlisting}

\paragraph{Prompt~2 (event-only, action-focused).}
Forces the model towards explicit action verbs and discourages purely
descriptive captions.

\begin{lstlisting}[style=prompt,caption={\texttt{event\_only\_prompt2} -- action-focused.},captionpos=b]
You are a video analyst. The frames below are sampled at regular intervals
from a video and shown in chronological order.
Task: identify the main ACTIONS and TRANSITIONS that occur throughout the video.
Rules:
- Focus on what people are DOING, not just what is visible
- Each event must describe a distinct activity or location change
- Merge consecutive similar actions into one event
- Be specific: use action verbs (running, climbing, jumping, talking, eating...)
- Return between {min_events} and {max_events} events
\end{lstlisting}

\paragraph{Prompt~3 (timestamp, Step-5 style + proportional timestamps).}
The Step~5 event detector is run per temporal segment, then approximate
\texttt{MM:SS--MM:SS} intervals are assigned proportionally inside each
segment. This avoids the very unreliable behaviour we observed when the VLM
itself was asked to emit timestamps.

\paragraph{Prompt~4 (timestamp, alternative scene-transition emphasis).}
A more concise prompt that asks for short, concrete events covering the
whole timeline; same proportional timestamp assignment.

\begin{lstlisting}[style=prompt,caption={\texttt{timestamp\_prompt2} -- alternative timestamp-aware prompt.},captionpos=b]
The frames below are sampled in chronological order from a single video segment.
List the most salient ACTIONS and SCENE TRANSITIONS that you can observe.
Rules:
- Each event must be ONE short sentence (max 12 words).
- Do not chain multiple actions with commas into one event.
- Group truly repeated actions into one event only if they happen at the SAME moment.
- Separate distinct moments / transitions into different events.
- Return between {min_events} and {max_events} events.

Format strictly as:
1. short action description
2. short action description
\end{lstlisting}

      & Reduces multi-event ``mega-sentences'', sharper parsing. \\

  \end{tabularx}
\end{table}

\subsection{Output Parser}
\label{subsec:vlm-parser}

A small regex-based parser converts the raw VLM text into a structured
\texttt{Event} record:

\begin{lstlisting}[style=prompt,caption={Parser pseudocode.},captionpos=b]
def parse_events(raw_text):
    events = []
    for line in raw_text.splitlines():
        line = line.strip()
        if not line: continue
        # strip "Salient event N:" / "N." / "N)" prefixes
        line = re.sub(r"^[Ss]al[ei]e?nt\s+[Ee]vent\s+\d+\s*:\s*", "", line)
        line = re.sub(r"^\d+[\.)\-]\s*", "", line).strip()
        ts = re.search(r"(\d{1,2}:\d{2})\s*[-]\s*(\d{1,2}:\d{2})", line)
        events.append({
            "description": re.sub(r",?\s*\d{1,2}:\d{2}.*$", "", line),
            "start": ts.group(1) if ts else None,
            "end":   ts.group(2) if ts else None,
        })
    return events
\end{lstlisting}

\subsection{Word-Embedding Similarity Evaluation}
\label{subsec:vlm-similarity}

For each annotated event $a_i$ we compute the cosine similarity with every
predicted event $p_j$ from the same video using a sentence-transformer
encoder $\phi(\cdot)$:
\begin{equation}
  s(a_i,p_j) \;=\; \frac{\phi(a_i)\cdot \phi(p_j)}{\lVert\phi(a_i)\rVert\,\lVert\phi(p_j)\rVert}.
  \label{eq:cos}
\end{equation}
The best match for annotation $a_i$ is $\hat{p}_i = \arg\max_j s(a_i,p_j)$
with score $s_i^\star = \max_j s(a_i,p_j)$. An annotation is considered
\emph{retrieved} if $s_i^\star \geq \tau$ for a chosen similarity threshold
$\tau$. Recall at threshold $\tau$ is therefore
$\mathrm{Recall}(\tau)=\frac{1}{N}\sum_i \mathbf{1}[s_i^\star\geq\tau]$
with $N=38$ annotated events across the four videos.

\paragraph{Interpretation.}
\begin{itemize}[leftmargin=1.4em]
  \item \textbf{Pixel-level events} (physical actions, scene transitions,
        object interactions) are missed mostly because of paraphrase
        differences: similarity scores are non-trivially high
        (mean $\approx 0.28$--$0.32$) but never quite reach the threshold.
        These are recoverable with a softer threshold or a stronger
        embedding model.
  \item \textbf{Non-visual events} (titles, credits, interviews, narrative
        context) sit at very low similarity (mean $\leq 0.24$) -- the VLM
        simply cannot recover information that is not directly observable in
        the sampled frames.
  \item \textbf{Long montage / compound annotations} are inherently
        mismatched: a single annotation describes 30--60\,s of video that
        the VLM legitimately splits into several short events, none of which
        is individually similar enough to the umbrella annotation.
\end{itemize}

\subsection{Discussion}
\label{subsec:vlm-discussion}

Three observations are worth highlighting:

\begin{enumerate}[leftmargin=1.4em]
  \item \textbf{Timestamped predictions strictly dominate event-only ones.}
        Splitting the video into temporal segments forces the VLM to
        attend to the late portion of the clip, which the single-shot
        event-only strategy systematically ignores. This roughly
        \emph{doubles} recall at every threshold up to $\tau=0.45$.
  \item \textbf{Asking the VLM for timestamps directly is unreliable.}
        Across $>$30 attempts SmolVLM2 produced inconsistent or
        ill-formatted \texttt{MM:SS} output, sometimes after 16--20\,min
        of generation. Replacing this by a deterministic proportional
        assignment within each temporal segment is both faster and more
        accurate.
  \item \textbf{The 50\,\% recall ceiling is partly an evaluation artefact.}
        Sentence-embedding similarity penalises legitimate paraphrases. The
        threshold sweep (Table~\ref{tab:vlm-threshold}) shows that lowering
        $\tau$ to $0.35$ recovers an extra $\sim$5\,\% absolute recall
        without obviously polluting the matches.
\end{enumerate}

\subsection{Conclusion}
\label{subsec:vlm-conclusion}

The best configuration is the timestamped, scene-transition--oriented prompt
(\texttt{timestamp\_prompt2}) running on per-segment inference with
deterministic proportional timestamps. It retrieves \textbf{19/38 = 50\,\%}
of the annotated events at threshold $\tau=0.40$ and \textbf{55.3\,\%} at
$\tau=0.35$. The remaining failures are dominated by content that is not
directly observable in sampled frames -- titles, credits, interviews and
narrative context -- which would require either a richer modality (audio,
on-screen text OCR) or a larger VLM with stronger temporal reasoning.
